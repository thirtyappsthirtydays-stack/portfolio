03 · Develop

Three layouts for one question

I tested three layouts for a role’s candidates as clickable wireframes with recruiters.

  • DroppedTable firstReasons hid behind a hover, so recruiters sorted by score and stopped
  • Pipeline tabPipeline boardGood for moving people between stages, poor for comparing them
  • ChosenRanked list with evidenceRecruiters could compare, check and explain in one place

Four questions, in the order a recruiter asks them

1234
  1. 1Role and statusWhere am I, and is this role on track?
  2. 2Ranked listWho is best? A gold score on each line.
  3. 3EvidenceWhy? Reasons stay open beside it.
  4. 4ActionWhat next? One purple button per view.

Design system

Purple for actions, gold for AI evidence

Every style is a Figma style and a code token with the same name.

14Text styles30Colours in 3 ramps9Spacing steps4Radii

Each Figma component maps one to one to a coded one. The system became the base every later feature was built on.

04 · Deliver

The recruiter’s workspace

A role-centred workspace where every score shows its reasons. It launched as CereHive’s MVP.

In the MVPOne workspace per role: Matches, Pipeline, Sequences, Interviews and the briefOne search across the client’s ATS, CereHive’s talent pool and IndeedA reason and its source beside every scoreA recruiter check on each must-have
Trade-offsRecruiters confirm every matchNobody is rejected automatically, so every shortlist needs a recruiter’s check. In return, she can explain every name on it.A ranking that doesn’t learn yetRecruiters’ checks don’t change the ranking in the MVP. Using them to tune each role’s ranking is the next step.
